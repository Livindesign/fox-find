# 本机响应修复 · 0.0.1 build 36

本轮只针对交互卡顿与后台资源争用。使用小范围、单任务验证；没有重复运行 30 万条滚动或 400 次切换压测。此版本仅安装到本机，未发布 GitHub Release。

## 实际修改

- OCR/文档识别与语义建库共享一个后台执行名额，避免两个重任务同时运行。
- 前台语义查询先取消后台任务，等后台退出后才启动模型；等待最多 1 秒，超时提供明确状态，文件名/已索引文字结果仍可使用。
- 建库开始前释放闲置查询模型；文本和图片查询只保留当前一种 worker，避免多个模型副本叠加驻留。空闲释放任务合并。
- 系统报告内存压力时取消建库、释放查询模型，暂缓新的模型工作；压力解除并空闲后恢复。OCR 也遵守节能和高温退让。
- 文件名/已索引文字仍立即搜索；描述搜索在停止输入 300 ms 后才执行。过期输入和已清空的查询不会启动模型；输入法尚未确认的组合文字不启动 AI 查询。
- 列表、宫格的未变化控件不重复设置 frame；摘要宽度只在文本变化时测量；滚动占位图标复用。
- 保留上轮已完成的持续滚动避让、隐藏列表延后刷新、宫格复用与崩溃修复。
- 打包默认限制 Swift 编译并发，本轮以单任务、低优先级构建。

小型交互是当前测量，不能与之前 30 万条结果、400 次切换的测量直接计算提速比例。尚不能据此宣布大库、真实模型持续建库或所有预览场景均达到发布标准。

当前仍为本地候选版，不改变发布阻断结论。大型数据集及真实模型并行交互的长期验收另行安排，避免再次占满用户电脑。

## 启动检查发现的问题（build 36 未通过交付验收）

安装后首次检查记录到 Fox Find 的 `ps %cpu` 为 635.7%，RSS 242 MB。立即做了唯一一次 1 秒被动采样并终止本次 Fox Find 启动，未触碰其他应用。这个瞬时读数不能当作持续占用或前后对比基线。采样显示正文 SQLite 读取以及 AI 对话历史导入并行存在；导入的 CPU 节流正在睡眠，不能据此把峰值全部归因于导入。

继续修复见 build 37 记录。build 36 不作为已经解决启动占用的版本交付。
