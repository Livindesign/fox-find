# 省略日期语句修复 · 0.0.1 build 34

## 问题与当前行为

安装版 build 33 将 `八月图片`、`八月的图片` 当作未识别条件后退回全文匹配，因而可能只找到包含这句话的设计文档。本轮直接修复原生应用的解析和索引查询，不依赖向量模型理解月份。

| 输入 | build 34 行为 |
| --- | --- |
| 八月图片 / 八月的图片 / 8月图片 / ８月的图片 | 所有年份的八月 + 图片；日期依据默认为修改时间，显示在标签中 |
| 2024年八月的图片 | 2024 年八月修改的图片 |
| 八月修改的图片 | 所有年份的八月修改时间 |
| 八月拍摄的图片 | 所有年份的八月拍摄时间；严格使用拍摄元数据 |
| 八月图片.jpg | 保留为文件名匹配，不拆成日期条件 |

没有明确写“拍摄”的月份查询，采用可见、可删除的修改时间条件。此默认值不代表拍摄、接收或下载时间。微信等来源的完整识别、复杂组合 QueryPlan 和全部语义语料仍未实现，不将这一修复宣传为任意自然语言搜索。

## 查询实现与性能

修改月份通过 `dm:month8` 查询已有文件索引。每次解析预计算月区间，匹配循环二分比较索引中的时间戳，不逐文件执行 Calendar 或读取图片。纯日期/类型条件不启动内容搜索、向量推理或拍摄元数据补查。

Release 核心对象、`swiftc -O` 独立程序，固定 1,000,000 条合成索引，8 次查询：

- 每次准确返回 66,667 张八月图片。
- 8 个样本中第 5 个耗时 **8.87 ms**，最大 **10.48 ms**。
- 查询循环不读取文件；这里只计已有内存索引的筛选，不包括初次索引、结果排序、界面展示或拍摄元数据扫描。
- 未与旧版做相同工作负载对照，不计算“提升倍数”。

原始记录：`build/acceptance-month34/month-benchmark.log`；可复现输入生成代码：`Tests/OilFindCoreTests/CalendarMonthTests.swift`。独立运行器位于 `build/acceptance-month34/month-benchmark.swift`，链接当前 Release 核心对象。
