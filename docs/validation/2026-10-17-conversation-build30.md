# 0.0.1 build 30：对话打开与预览窗口

2026-10-17，Apple M1 Pro / 16 GB / macOS 27.0.1。此包为本机验收候选，不是公开发布。

## 改动

- 原会话链接明确派发给对应客户端，优先使用正在运行的应用。校验应用身份，排除隐藏备份和废纸篓路径；不会修改系统 URL 默认处理程序。
- 等待 macOS 的异步打开回调，阻止同一会话重复提交；修改查询、关闭来源后忽略旧回调，避免误关新的搜索。派发失败保留搜索并显示原因，不再悄悄用副本替代原会话。
- 预览底部直接提供「打开原会话」「复制内容」；只有命令行入口的 Claude Code 会话提供「复制继续命令」，不自动运行命令。
- 预览采用主界面同款中性灰毛玻璃，完整覆盖原生标题栏；保留原生关闭、缩放与拖动能力。深浅色、最小宽度及按钮间距均有检查。正文仍按字面文本呈现，不执行消息中的 HTML。
- 长对话使用非连续排版，实际布局后再定位关键词。补充空内容、截断、复制反馈，以及 Esc / ⌘W 关闭。隐藏搜索窗口时撤销尚未完成的预览，避免迟到弹窗。
- 搜索框已有焦点时不重新绑定编辑器，保留光标与选区；对字面查询关闭 macOS Writing Tools 自动改写入口，不改变系统输入法或键盘设置。

## 跳转证据与边界

安装客户端中已核对 `codex://threads/<UUID>` 的路由处理。修改前的一次实际 Return 操作，客户端日志已经记录目标 `/local/<UUID>` 路由，因此不能断言所有旧版跳转都失败，也不能把本轮变更说成已根治所有来源的导航问题。

本机存在多个同 bundle ID 的历史客户端备份；当前 LaunchServices 解析恰好指向正在运行的客户端。这不是本次故障的已证实根因，明确选择客户端是消除歧义的改进。

Computer Use 拒绝读取 Codex/ChatGPT 自身界面，因此该客户端只能用打开回调与路由日志核对，不能伪称完成了目标会话的视觉终检。没有修改客户端、绕过此限制或把其个人对话内容加入测试资产。Claude / WorkBuddy 的真实客户端逐会话导航仍待终检。

## 性能记录

46.2 万字节、200 条合成消息：第一轮全量中预览初始化及布局中位数 19.81 ms，最大 73.28 ms（5 次）。4,000 段对话查询、500 条结果：禁用应用结果与解压缓存时 P95 15.80 ms，虚拟列表选择/布局 P95 0.63 ms，7 个行视图。不是冷磁盘速度或显示 FPS。

首次组合压力测试 **失败**：40 轮切换 P95 711.56 ms、最大 779.95 ms，超过 250 ms 限制；没有隐藏该结果或放宽阈值。同组复跑在没有修改结果渲染代码的情况下恢复至 P95 35.86 ms、最大 42.48 ms，因此不能拿这两次数据宣称优化了 95%。尚未定位首次长停顿的唯一根因。

采样发现首次输入焦点会加载系统 Writing Tools 组件；本轮减少重复焦点操作并关闭搜索输入中的该入口。这是有证据的局部改进，不等于证明它解释了全部视图切换停顿。

同组复跑：12 张 4032×3024 JPEG 首张 29.42 ms、全部 51.72 ms，缓存复用 0.64 ms；1,000 文件列表/宫格滚动主线程工作 P95 1.44 / 2.70 ms；Quick Look 窗口出现 580.09 ms，仍不代表图片首帧已完整显示。更早的 0.92 秒预览和大库长帧问题不能据此宣布全部解决。
