# 本机资源与交互修复 · 0.0.1 build 37

延续 build 36 的后台资源预算、模型释放、输入防抖及视图布局修复。本轮保持单编译任务、低优先级；没有跑大库压测，没有清理用户索引、模型或其他应用。

## 本轮修复

- 文件名匹配和目录匹配最多使用 2 个并行工作单元。多磁盘逐来源查询，避免来源并行再乘核心并行。后台目录扫描默认也限制为 2 个工作单元。代价是大型全量索引可能更慢，优先保留桌面交互能力。
- 带尾斜杠的路径条件用于正文/语义候选验证时，沿当前文件父目录检查，不再为每个候选重建全盘目录 mask。
- 正文查询合并所有来源为一次数据库查询，减少短词不能走 trigram MATCH 时的重复正文扫描。没有把用户库重新建索引。
- 正文搜索在输入停顿 150 ms 后执行；文件名搜索立即执行。过期代次先取消，窗口隐藏后也取消正文/语义查询及元数据细化工作。
- AI 对话历史导入在启动、输入、滚动、切换视图后等待 8 秒空闲，再继续已有进度；目录首次建库时也让出资源。内存压力触发取消，恢复后等待空闲。已索引对话仍可搜索。
- 原有 AI 历史导入线程 CPU 预算保留，防止空闲导入持续占满 CPU。
