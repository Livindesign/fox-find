# Fox Find：小而美与 AI 机会评估

调研日期：2026-10-17。状态：用户已批准按研究结论继续评估并开发。阶段进度见[本地对话与排序验收](../validation/2026-10-17-ai-search-build29.md)。

建议定位：**记得一点线索，就能找回文件、素材和当时的工作上下文。**

“顶尖”的衡量是正确率、找到并打开目标的时间、后台资源占用和信任感。新框架与模型只在改善这些结果时引入。保留一个搜索入口、一个结果区、按需预览，扩展能力主要出现在结果和上下文操作中。

## 1. 已核对的事实

### Oil Find 上游

[官方更新日志](https://find.oiloil.org/changelog) 当前最新是 1.7.1（2026-10-17）。

- 1.7.0：本地 AI 对话搜索，支持 Claude Code、Codex、WorkBuddy；来源可单独开关，查标题与正文并打开原会话；增量同步、避免重读不变会话。
- 1.7.1：修复部分设备启动退出、更新失败、AI 话题图标打包与缺失处理。
- 1.6.1–1.6.2：索引任务分段、前台输入让路、合并维护任务、避免慢扫描结束后立即再扫描。

已通过 GitHub API 核对 AI 对话搜索确实进入公开 MIT 仓库，并非仅在商业版宣传页出现：[提交 b089cdd9](https://github.com/oil-oil/oil-find/commit/b089cdd9adb025fdc55dd89d19790db4c039334a)。它包含 AITopics 模块、来源监听、同步预算与测试。

建议逐项比较后移植来源适配与调度思路；当前 Fox Find 的 UI、内容索引和运行进程已有较大差异，不能整包覆盖。AI 对话搜索本身已有上游实现，不能作为我们的独有卖点。

### Fox Find 当前基线

当前代码已有文件/应用搜索、OCR、文档内容、语义与相似图片、自然条件、列表/宫格、预览、收藏、离线盘索引、计算器、更新与引导。无需把已有功能包装成新规划。

语义模型是固定版本的 EmbeddingGemma 2 Q8_0，本地两文件约 865 MB；文字文件约 310 MB。调研基线的文字索引采用 FTS5 trigram，无 BM25 排序；本轮已为可索引的长关键词补充 BM25，中文短词保留完整字面查询。向量库仍用逐条相似度计算；照片元数据已有缓存，但尚无完整的按拍摄日期索引的数据库查询路径。上述为代码检查，非外部宣传。

Google 官方记录 EmbeddingGemma 2 于 **2026-10-06** 发布；官方模型支持多模态、分模块加载和 128/256/512/768 维向量。因此“换最新模型”不是首要问题，当前模型的使用方式仍有优化空间。[版本记录](https://ai.google.dev/gemma/docs/releases) · [模型说明](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2?hl=en)

## 2. 模块级机会

| 模块 | 建议方案 | 用户能感受到什么 | 代价与边界 | 顺序 |
| --- | --- | --- | --- | --- |
| 自然条件 | 统一、可验证的查询计划；常见表达走规则，复杂表达才调用系统/小模型 | “去年7月下载目录拍的照片”变成可编辑的类型、日期、位置条件；不支持的条件明确显示 | 模型只提议条件，日期/范围/否定必须校验；月份无年份要显示实际年份；歧义不能猜后静默执行 | P0 |
| 元数据与索引 | 类型、EXIF 日期、日期来源、在线状态、指纹入结构化索引；合并更新任务，前台优先 | 日期筛选无需每次逐张读照片；索引时输入和预览仍顺畅 | 数据迁移、断电恢复、事件丢失与重命名一致性需测试；未知 EXIF 不能拿修改时间冒充 | P0 |
| 排序 | 精确文件名优先，正文 BM25 与语义候选融合；必要时仅重排少量候选 | 相关文档更靠前；不会用“差不多”突破文件类型、日期、目录限制 | 中文短词/分词与 OCR 噪声需专门评估；重排增加延迟，不能默认每次触发 | P0/P1 |
| 模型与能耗 | 按需加载文本/图像能力；测试缩短向量、量化或硬件后端 | 仅搜文档的人少下载、少占内存；打字时不唤醒大模型 | 目前下载/进程逻辑需要适配；更换后端或向量规格要有索引版本与回滚 | P1 |
| 图片 | 局部选取主体再找相似图；按需生成少量画面标签 | “找这串手链的其他拍摄角度”，减少同背景图片干扰 | 主体分割可能出错；视觉相似不能证明是同一件商品；不默认全盘运行视觉大模型 | P1 |
| 文档预览 | 展示匹配原文、页码与日期来源；选中文档后可问一个问题 | “这份文件的交付时间在哪一段？”答案可点回原文 | 找不到证据就说明；文档内文本作为资料，不能成为执行命令；提取需页数与资源预算 | P1 |
| AI 对话 | 上游来源适配 + 会话、明确引用文件、项目路径的关联 | “上周讨论包装设计的对话和最后那个 PDF”能一起找到 | 只有显式链接/路径等证据才能确认关联；时间相近只能标为候选；各工具格式变化有维护成本 | P1/P2 |
| 视频与音频 | 指定目录的转写、时间戳片段、稀疏关键帧索引 | 搜一句台词或画面，直接跳到片段 | 首次索引、磁盘和电量成本较高；现有运行器不等于已支持音视频全流程 | P2 |
| 连接其他工具 | 只读本地 MCP：搜索、返回有限原文与来源；系统入口可评估 App Intents | Codex/Claude 能查到用户指定资料，少反复选文件、复制上下文 | 需限定目录和调用者；客户端可能把返回内容发往云模型，必须让用户清楚数据流向 | P2 |
| 性能与可靠性 | 搜索/预览/滚动/索引同时运行的固定场景，主线程与内存监测 | 对“不卡、不闪、不崩”形成持续验收 | 单个函数耗时不是实际帧率；模型自评分不能替代人工标注和真实结果检查 | P0 |

BM25 与融合不是新概念，但很适合当前缺口，无需引入服务器：
[SQLite BM25](https://www.sqlite.org/fts5.html#the_bm25_function) · [混合搜索与 RRF](https://www.elastic.co/docs/solutions/search/hybrid-search)。

## 3. 值得做小样验证的新技术

### A. Foundation Models + Core Spotlight

Apple 在 WWDC26 介绍了 SpotlightSearchTool：让语言模型调用应用自己的 Core Spotlight 索引，支持元数据与语义查询，结果可分批展示，并可按标识取回完整内容。[官方介绍](https://developer.apple.com/videos/play/wwdc2026/246/)

适合试验复杂表达的查询规划和有出处的文档回答。它不自动获得整个磁盘的内容，也不免除我们的索引、文件权限和结果校验责任。现有通用搜索链路继续工作；先用同一套中文样本比较再决定是否接入。

Foundation Models 新增了图像输入与更统一的模型接口；系统模型是否可用取决于系统、设备、地区、语言及用户设置。云端 PCC 与本地模型是不同的数据路径，不能把云端增强称为全离线。[官方介绍](https://developer.apple.com/videos/play/wwdc2026/241/)

### B. Vision 主体分割

WWDC26 的 tap-to-segment 支持通过点选等方式分离图片主体，首次使用需准备模型资源。[官方介绍](https://developer.apple.com/videos/play/wwdc2026/237/)

产品小样：用户在预览中圈住商品 → “找这个物体的相似图片”。只增加一个上下文动作，不增加常驻编辑器。

### C. EmbeddingGemma 2 的轻量配置，Qwen3-VL 作为对照

先评估当前模型的模态拆分和向量维度。768 维 Float32 改成 256 维时，**纯向量字节数减少 66.7%**，这不是整个索引/内存减少 66.7%，也不是已测出的提速。必须归一化、保证查询与库维度一致，并比较召回率。[Google 模型说明](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2?hl=en)

本轮已完成首个可复现的文本小样：24 篇合成文档/24 条中文查询，128 维第一名正确 22/24，256/512/768 维为 24/24。样本太小且不含图片，不据此切换默认配置；256 维进入扩大语料对照阶段。工具和逐项限制见[本轮验收](../validation/2026-10-17-ai-search-build29.md#向量维度小样)。

Qwen3-VL-Embedding/Reranker 的 2B 版本支持跨文字、图片、截图和视频检索，可作为中文复杂描述的小样对照。参数规模和重排推理成本较高，不建议仅因名称新就替换当前默认模型；模型卡成绩不能当作 Fox Find 实测。[官方模型卡](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B)

### D. Core AI / MLX 后端

Apple 的 Core AI 提供模型转换、提前编译、设备专门化、缓存与性能工具，适合探索更省资源的推理部署。[官方介绍](https://developer.apple.com/videos/play/wwdc2026/324/)

先挑一个当前实际使用的模型，比较冷启动、热推理、峰值内存、能耗与输出一致性。当前 llama.cpp 运行链路可继续保留；只有收益得到验证后再决定迁移，不同时常驻多套运行器。新 API 的最低版本与模型算子支持需 SDK 验证，保留 macOS 14 基础功能路径。

### E. Evaluations + Instruments

Apple 新 Evaluations 框架用于模型功能评估，Instruments 持续用于发现与验证响应性问题。[Evaluations](https://developer.apple.com/videos/play/wwdc2026/298/) · [响应性诊断](https://developer.apple.com/videos/play/wwdc2026/268/)

为 Fox Find 建立人工标注查询集、必须满足的过滤条件和确定的文件 ID；可借助模型生成更多句式，但不能只让模型给自己的搜索结果打分。我们的测试语料应覆盖日期、否定、错别字、中文短词、零结果、混合描述、缺失 EXIF 和权限状态。

## 4. 三个值得选择的产品方向

### 方向 A：找文件更可靠——推荐作为所有版本的基础

用户问题：“我记得一点线索，怎么还是找不到？”

目标体验：输入自然条件后，一眼看到软件理解的意思；找到结果可立即预览；没找到会解释是没有匹配、未索引、缺少权限还是缺少日期。

差异建立在中文表达、媒体/文档细节和稳定体验上。单纯增加启动器、计算器、剪贴板等功能的竞争较大；Raycast 已有完整工具组合。[Raycast 官方功能](https://www.raycast.com/core-features/file-search)

### 方向 B：创作者的素材找回——建议优先做出特色

三个候选场景：

1. “这张商品图的其他角度和原图在哪？”——主体相似度、文件名/目录关系、分辨率帮助找候选。
2. “上个月那批红色手链，横图、适合做封面”——严格时间/方向条件 + 视觉描述。
3. “这一版设计的源文件和导出图”——显式关联、名称/目录候选，人工确认配对。

关联结果明确区分“有证据的来源关系”与“可能相关”。版本选择可显示尺寸、修改日期、格式，不把最大/最新文件自动认定为正确终稿。

价值：高频、节省实际找素材时间，适合真实演示。代价：视觉检索质量、重复素材与源文件格式需要长期打磨。

### 方向 C：AI 工作上下文找回——中期增长机会

用户问题：“我记得在某个 AI 里讨论过，也生成过文件，但忘了是哪一次。”

候选体验：搜关键词 → 显示会话关键段落、明确关联的产物 → 打开原会话或产物。用户主动选定结果后，可以复制带出处的简短上下文，或授权 MCP 客户端读取。

[MCP 官方架构](https://modelcontextprotocol.io/docs/learn/architecture)支持用工具和资源提供上下文；它不保证各聊天产品都开放本地历史或写入接口。第一批只覆盖有明确本地来源的工具，不宣称能搜所有 ChatGPT/Claude 网页历史。

价值假设：用户使用的 AI 越多，找回跨工具工作资料的需求可能越明显。这个假设需要真实用户验证，不能据此承诺收入。

## 5. 推荐决策与验收

推荐组合：**A 为基础，B 为第一特色，C 留作下一阶段可选扩展。** 若首批目标用户主要是 AI 开发者，可把 B 与 C 的顺序互换。

小而美的具体约束：

- 一个搜索框；常用分类稳定，更多来源收在筛选内。
- 理解结果用可编辑条件显示；复杂问题才出现小型澄清入口。
- 预览承担证据与轻问答；不常驻第二套聊天界面。
- 按需下载与运行；首次引导只完成一个真实查找任务。
- 毛玻璃主要用于窗口层级，列表滚动不反复计算整窗模糊；尊重减少动态效果、减少透明度。

先建立约 200 条人工标注的固定查询集。以下是**拟定验收目标，不是当前已达到的成绩**：

| 检查 | 建议验收方式 |
| --- | --- |
| 条件正确 | 标注集内日期/类型/目录硬条件违规为 0；不支持的条件可见 |
| 相关性 | 对同一语料测 Precision@10、Recall@20；模型/排序变化与现有版本对照 |
| 首批结果 | 对已索引的典型文件名场景，输入到首屏 P95 目标 <100 ms；冷启动与索引另测 |
| 交互 | 用屏幕帧时间和主线程卡顿验证列表、宫格、空格预览，不把回调耗时当帧率 |
| 压力流程 | 索引进行中连续输入、清空、切换视图、快速预览；过期响应不得覆盖新搜索 |
| 资源 | 大库、长时间操作、内存压力下记录峰值和回落；按具体测试规模制定预算 |
| 发布 | 独立测试安装/更新/回滚、首次权限、至少另一台设备与较早受支持系统；每项留证据 |

当前仍以 0.0.1 私有候选验收为准。功能研发已获批准；公开发布仍须完成验收并经用户确认。
