# Fox Find UI 设计语言

状态：产品界面的实现与验收约束。以用户多轮确认的原生主窗口为基准；新功能必须延续，不从系统默认表单或临时配色重新开始。用户的新要求优先于本文件，变更时同步更新组件与规范。

## 设计理念

**安静、清楚、轻快。** 深色中性灰毛玻璃是全应用底色；通过空间、字重、明度和操作层级组织内容。玻璃提供轻微环境感，不让背景文字透读，不用蓝绿底色、彩色光晕或巨大的模糊阴影制造层次。

用户先看到正在处理什么，再看到可做什么。一个窗口只突出一个主要结果；信息按任务分组，不能把标题、技术解释、状态和所有按钮等权平铺。功能能执行不等于界面完成。

## 唯一实现来源

| 用途 | 代码入口 | 规则 |
| --- | --- | --- |
| 色彩、圆角、间距、状态、动效 | `Sources/OilFindApp/Theme.swift` | 新界面引用语义 token，不复制十六进制色或另起蓝灰主题 |
| 整窗玻璃与标题栏 | `PanelSurface` / `SurfaceTint` | 每个窗口一层系统 blur，标题栏与正文连续覆盖 |
| 内容分组 | `GlassSection` | 无独立 blur 的中性灰薄底板，仅用于真实的信息分组 |
| 操作按钮 | `GlassButton` | primary / secondary / quiet 三层；图标与文字一起居中 |
| 辅助窗口列表 | `GlassListRow` | hover 和选中复用同一个圆角路径，不调用系统蓝色选中绘制 |
| 主窗口筛选与导航 | `ChromeButton`、`FilterTitleView` | 保留已调好的左对齐、16 pt 内边距和字形垂直居中 |
| 设置页适配 | `SettingsGroup`、`SettingsButtonStyle`、`SettingsShell` | SwiftUI 适配器使用同一组 Theme token，不另立视觉规范 |
| 滚动 | `ResultScrollView`、`TransientResultScroller`、`SettingsScrollStyling` | 使用现有暂显滚动条，不叠加第二条 |

`Workflows/WorkflowChrome.swift` 只负责收集内容的呈现格式，不再定义功能专属按钮和卡片。
已有组件能满足时直接复用；确需新增组件，应先在本规范说明它解决的交互差异，再实现共享组件。不能把“不一样”当作新功能的默认值。

## 色彩与材质

- 应用自有窗口使用 dark Aqua。主窗口、引导、设置、更新、菜单、对话和二期工具保持同一深色语言。
- 玻璃 tint 为等通道中性灰：`Theme.glassTint(dark: true)`，sRGB 灰度 0.115；遮罩透明度 0.86。减少透明度时使用不透明中性灰。
- 窗口仅一层 `NSVisualEffectView`；内部组底白色 3.5%，细描边 7.5%。不能每张卡再加实时毛玻璃。
- 文字按主标题、正文、辅助、元数据分级。禁用态可更弱，必要信息不能伪装成禁用态。
- 主操作使用浅中性灰实底、深色字；次操作使用轻灰底；局部移除等使用 quiet。不能让所有按钮都像主操作。
- 产品图、真实文件图标、警告/错误等语义颜色保留。用户主动设置的按钮强调色只用于既有强调位置，不染整窗或引入新功能专属配色。
- 系统文件选择器、权限面板等由 macOS 管理，不仿造系统授权 UI；应用自有 sheet 仍遵守上述语言。

## 尺度与布局

以下为 AppKit 逻辑点（pt），2× 屏幕对应双倍像素。

| 层级 | 规格 |
| --- | --- |
| 窗口 | 22 pt 连续圆角 |
| 内容组 | 14 pt 连续圆角，分组间距 16 pt |
| 操作按钮 / 筛选 / 辅助列表态 | 10 pt；同组件 hover、pressed、selected 的形状不变 |
| 常规操作按钮 | 高 36 pt；底部主操作 38 pt；左右留白至少 16 pt |
| 间距 | 8 / 12 / 16 / 24 pt；窗口主内容外边距 24 pt |
| 标题 / 分组 / 正文 / 辅助 | 23 semibold / 13 semibold / 12–14 / 10.5–12 pt；中文、英文都实际检查 |

同一行内容沿共同基线；标题、说明、列表左缘一致。筛选组按内容宽度排列，不能靠过大固定空隙分隔。长文件名中间省略、路径辅助显示并提供完整 tooltip；不能挤掉操作。

大内容滚动，主操作保持可见。表单有明确标签，不能只靠 placeholder。空态给出一个明确下一步，不用一整屏技术参数解释。

## 交互约定

- 所有可点击元素有 hover、pressed、disabled；键盘可聚焦控件有 focus。图标按钮有辅助功能名称与 tooltip。
- 图标来自现有 FunctionalIcons / SF Symbols；文件与应用使用正确的实际图标。旋转箭头固定中心，不能随展开改变占位。
- 菜单紧凑、细边界和轻阴影；点击外部及 Esc 关闭。操作菜单不再添加冗余“搜索操作”输入框。可用项目由文件能力统一决定。
- 应用自有菜单统一图标＋文字，使用 `MenuIcons` 补齐旧菜单；菜单或操作浮层显示时，底层列表暂停 hover。系统共享/文件选择菜单保留系统行为。
- 辅助窗口由 `AuxiliaryWindows` 记录返回关系。重新进入搜索先隐藏旧辅助窗口；关闭预览返回搜索，替换窗口或打开外部应用不触发旧回调。
- 提示状态用限宽、左对齐的短标题＋说明＋一个主操作。权限问题为下方次要入口；操作反馈原位替换默认说明，不叠两行同义文案。
- 主搜索列表全宽显示；不恢复旁边常驻的大缩略图。按空格打开预览，再按空格或 Esc 关闭；编辑输入时尊重光标与输入法。
- 引导与主窗口等高；关闭后记住，只从菜单重开。圆形前后按钮放在页码两侧。
- 细滚动条仅滚动/拖动时显示，位置跟随内容；不裁切右侧，不占用重复轨道。
- 原生编辑支持复制、粘贴、全选、撤销；非当前窗口不能抢走快捷键；文件面板打开时不转发给后面的搜索框。
- 耗时操作显示进度/状态、限制重复触发，关闭能取消；失败状态保持恢复入口。

## 动效与性能

复用 `Theme.Motion`：hover / press 80 ms、内容淡入淡出约 120 ms；窗口与引导使用已实现的轻微位移/弹性。Reduce Motion 时降级为短淡入或静态。动画不能改变点击区、启动布局抖动或强迫用户等待。

不为装饰添加无限动画、每行 blur 或昂贵阴影。复用列表 cell；图片异步、限并发、限尺寸，窗口关闭取消任务。不得为验证 UI 启动全库扫描、模型常驻或并行压力测试。

## 二期界面结构

- **收集篮**：跨多次搜索暂存文件引用和对话摘录。左侧已收集内容和文件复制/导出；右上可选清单名与下一步；右下展示将要复制的内容。底部主操作“复制清单与摘录”，次操作“保存 Markdown”。默认说明复制不含文件正文；复制成功原位反馈。入口及空态说明用途，不使用“继续资料”等生僻名称。
- **原文件对照**：左侧候选；右侧等尺寸参考图和候选图；下方判断依据、文件名和路径。底部主操作“加入收集篮”；技术上限放到 tooltip，实际状态仍明确报告。
- **对话预览**：连续玻璃标题栏、宽阅读区、底部清晰的打开/复制/摘录动作。摘要与来源说明让位给对话正文。

## 每次 UI 变更的完成门槛

提交前在验证记录逐条注明“通过 / 未验 / 不适用”，不能把编译成功当作 UI 验收：

1. 读本规范并指出复用的组件；新模式先补组件与规范。
2. 用合成数据检查原生窗口：空、正常、长文本、禁用、选中、失败/处理中（按改动范围）。截图不用用户真实文件或对话。
3. 中英文检查主操作、溢出、截断与最小窗口尺寸。深色中性灰、标题栏连续、hover/selected 圆角一致。
4. 实际点击和键盘验证本次改动的主流程，检查关闭/返回/再打开；不能只看静态截图。
5. 一次低优先级、单任务的相关回归；保留日志和界面证据，结束后释放测试进程。
6. 区分代码完成、原生体验验收、用户确认、合并和发布。未验项不得写成“全部解决”。

修改视觉标准必须同时修改这里和共享实现。新功能不得绕开这份约束。
